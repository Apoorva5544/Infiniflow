RETRIEVAL PIPELINE

From Upload to Answer

Every query flows through a deterministic pipeline: ingest, embed, retrieve, rerank, reformulate, generate.

STAGE 01 upload_file

PDF Ingestion

PyPDFLoader with FlateDecode recovery for corrupted PDFs. RecursiveCharacterTextSplitter (1000 chars, 200 overlap).

bolt Corruption recovery built-in
STAGE 02 database

Embed & Store

ONNX MiniLM embeddings (384-dim, ~50MB RAM). Dual backend: ChromaDB for dev, PGVector for production.

lock Per-workspace isolation
STAGE 03 manage_search

Hybrid Retrieval

EnsembleRetriever combining vector search (0.6 weight) + BM25 keyword search (0.4 weight). Returns top-5 each.

trending_up Semantic + keyword coverage
STAGE 04 · CORE psychology

Rerank + Reformulate

Cross-Encoder ms-marco-MiniLM re-ranks retrieved candidates down to top-5. History-aware retriever reformulates follow-ups into standalone queries.

auto_fix_high Cross-Encoder + LLM reformulation
STAGE 05 verified

Generate + Cite

Groq LLM (qwen3.8-27b) with SSE token streaming. Citation engine returns source, page, chunk text, and relevance score.

check_circle Verifiable source attribution

Hybrid Search with Cross-Encoder Reranking

Vector search finds semantically related chunks. BM25 finds exact keyword matches. Cross-Encoder ms-marco-MiniLM re-ranks the union to find the true top results.

// EnsembleRetriever weights from rag_engine.py:316-319
ensemble_retriever = EnsembleRetriever(
    retrievers=[bm25_retriever, vector_retriever],
    weights=[0.4, 0.6]  // 60% semantic, 40% keyword
)

// Cross-Encoder reranker: candidates → top-k (default 5)
reranker = CrossEncoderReranker(
    top_k=5,
    max_chars=512
)
// Model: cross-encoder/ms-marco-MiniLM-L-6-v2
// Graceful fallback to truncation if model unavailable
● Fallback-safe reranker ● Configurable weights ● BM25 index cached per store

Streaming Responses & Semantic Caching

Server-Sent Events deliver tokens as they're generated. Semantic cache (Redis-backed or in-memory) avoids redundant LLM calls for similar queries within a 24h TTL.

SSE Event Types
start — stream initiated
sources — citations pushed
token — individual LLM tokens
done — stream complete
Cache Config
Backend: Redis or in-memory
TTL: 24 hours
Max entries: 256 (LRU)
Scope: per-workspace
Exact match + optional similarity
POST /api/v1/workspaces/{id}/query/stream — SSE with token-by-token delivery
BUILT-IN EVALUATION

Evaluation Harness

Automated retrieval and faithfulness metrics with CI integration. Measure precision@k, recall@k, MRR@k, and LLM-as-judge faithfulness against a deterministic test corpus.

Context Precision@5
precision_at_k
Fraction of top-5 chunks carrying evidence
Recall@5
recall_at_k
Expected sources found in top-5 retrieval
MRR@5
mrr_at_k
Reciprocal rank of first correct source
Faithfulness
LLM-as-judge
Answer grounded in retrieved context (0–1)

Drop-in API. Up in Minutes.

Full OpenAPI docs at /api/docs. 19 endpoints across auth, workspaces, documents, query, analytics, and system health.

bash - infiniflow-query.sh
POST /api/v1/workspaces/{id}/query/stream
# 1. Sign up and get a JWT token
curl -X POST https://infiniflow-prod.onrender.com/api/v1/auth/signup \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"secret","full_name":"You"}'
# 2. Create a workspace and upload a PDF
curl -X POST https://infiniflow-prod.onrender.com/api/v1/workspaces \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5..." \
  -d '{"name":"My Workspace","description":"Team docs"}'

curl -X POST https://infiniflow-prod.onrender.com/api/v1/workspaces/{id}/upload \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5..." \
  -F "file=@report.pdf"
# 3. Query with streaming SSE and citations
curl -N -X POST https://infiniflow-prod.onrender.com/api/v1/workspaces/{id}/query/stream \
-H "Authorization: Bearer eyJ..." \
-d '{"question":"What was the revenue?","stream":true,"include_citations":true}'
